System Architecture

System Overview

The Philips Lab ecosystem is a full-stack, multi-tier platform consisting of four repositories/modules:

  1. lab-wxapp — WeChat mini-program (consumer-facing), built with UniApp + Vue 2, targeting WeChat (mp-weixin) as primary platform
  2. lab-admin-web — Internal admin SPA (Vue 2), serving CMS, Mall/FSS, and Common platform operators
  3. lab-manage-backend — Two standalone Spring Boot admin backend services (lab-admin and lab-fss-admin) that serve the admin web portal
  4. lab-backend — Spring Cloud microservices platform (20 sub-modules) serving the consumer mini-program via a gateway

All four modules share the same production domain (www.phlab.philips.com.cn) with path-based routing. The consumer mini-program hits /lab/* paths; the admin portal hits /ph-lab-admin/* and /lab-fss-admin/*.

Diagram 3 — Authentication Flows

Shows how consumers and admins authenticate, and how tokens are validated on each request.

sequenceDiagram
    participant WxApp as lab-wxapp
    participant Gateway as ph-lab-gateway
    participant UserSvc as ph-lab-user
    participant Redis as Redis

    Note over WxApp,Redis: Consumer Login
    WxApp->>UserSvc: WeChat OAuth code
    UserSvc->>Redis: store token - userId mapping (TTL)
    UserSvc-->>WxApp: authToken

    Note over WxApp,Redis: Subsequent Requests
    WxApp->>Gateway: GET /lab/cms/... + Authorization: Bearer {token}
    Gateway->>Redis: GET LOGIN_TOKEN_KEY:{token}
    Redis-->>Gateway: {userId, username, ...}
    Gateway->>UserSvc: request + X-User-Id header
    UserSvc-->>WxApp: response

    participant AdminWeb as lab-admin-web
    participant LabAdmin as lab-admin
    participant ShiroRedis as Redis (Shiro)

    Note over AdminWeb,ShiroRedis: Admin Login
    AdminWeb->>LabAdmin: POST /admin/login {username, MD5(password)}
    LabAdmin->>ShiroRedis: create Shiro session
    LabAdmin-->>AdminWeb: {labFssAdminToken, permissionCode[], platforms[]}
    AdminWeb->>LabAdmin: GET /csrf/token
    LabAdmin-->>AdminWeb: {token, headerName}

    Note over AdminWeb,ShiroRedis: Admin Mutating Requests
    AdminWeb->>LabAdmin: POST /admin/... + X-CSRF-Token: {token}
    LabAdmin->>ShiroRedis: validate session
    LabAdmin-->>AdminWeb: response

Component Catalog

lab-wxapp (Consumer Mini-Program)

  • Purpose: WeChat mini-program for Philips Lab end consumers
  • Responsibilities: Content browsing, community/UGC, e-commerce shopping, loyalty/points, marketing activities, after-sales, trade-in, warranty, gift cards, VR/game experiences
  • Type: Application (Frontend)
  • Architecture: UniApp + Vue 2, Vuex state management, uni.request HTTP client, sub-package lazy loading (18 sub-packages)
  • External Dependencies: uView UI, Pixi.js 6.x, RxJS, Sensors Analytics SDK, flyio, uni-simple-router, timeago.js

lab-admin-web (Admin SPA)

  • Purpose: Internal back-office management portal for CMS, FSS/Mall, and Common platform operators
  • Responsibilities: Content management, marketing campaign management, member management, e-commerce operations, system administration
  • Type: Application (Frontend)
  • Architecture: Vue 2 SPA, hash-mode routing, Vuex, two Axios instances, RBAC permission system
  • Three Platforms: /cms (CMS), /mall (FSS), /common (shared)
  • External Dependencies: Element UI, ECharts, TinyMCE, WangEditor, Fabric.js, Tailwind CSS

lab-manage-backend / lab-admin (CMS Admin Backend)

  • Purpose: Backend service for the CMS platform of lab-admin-web
  • Framework: Spring Boot 2.7.18, Java 8
  • Auth: Apache Shiro + shiro-redis, JWT (jjwt 0.9.1), MFA via TOTP
  • External Dependencies: MySQL (Druid), Redis (Redisson), Elasticsearch, RabbitMQ, Nacos, XXL-Job, Tencent VOD, Aliyun SMS, AWS S3 SDK v2, ZXing, EasyExcel, Feign

lab-manage-backend / lab-fss-admin (FSS Admin Backend)

  • Purpose: Backend service for the Mall/FSS platform of lab-admin-web
  • Framework: Spring Boot 2.7.18, Java 8
  • Auth: Apache Shiro + shiro-redis
  • External Dependencies: MySQL (Druid), Redis, Elasticsearch, RabbitMQ, Nacos, Seata 1.6.1, XXL-Job, AWS S3 SDK v2, Sensors Analytics SDK, ZXing, EasyExcel, Feign, dynamic-datasource

lab-backend / ph-lab-gateway (API Gateway)

  • Purpose: Spring Cloud Gateway — single entry point for all consumer mini-program traffic
  • Responsibilities: Token-based auth (Redis session lookup), XSS filtering, URL blacklist, Referer validation, request statistics, inner-header stripping, routing to downstream microservices
  • Key Filters: AuthFilter, XssFilter, BlackListUrlFilter, RefererFilter, StatisticsFilter

lab-backend / ph-lab-user (User Service)

  • Purpose: Consumer user management and authentication
  • Responsibilities: WeChat OAuth login, phone binding, user profile, interest preferences, member points, token issuance/refresh

lab-backend / ph-lab-cms (CMS Service)

  • Purpose: Content management for consumer-facing content
  • Responsibilities: Articles, topics, UGC notes, videos, activities, surveys, landing pages, renovation pages

lab-backend / ph-lab-activity (Activity Service)

  • Responsibilities: Draws/lotteries, clock-in, seckill-integral, new product trials, store activities

lab-backend / ph-lab-aftersales (After-Sales Service)

  • Responsibilities: Openbox, self-service handbook, OHC parts

lab-backend / ph-lab-furnish (Page Builder Service)

  • Responsibilities: Page template storage, furnish tab management, config

lab-backend / ph-fss-* (FSS Microservices)

  • ph-fss-product: Product catalog, categories, specifications, shopping cart
  • ph-fss-order: Order lifecycle management
  • ph-fss-pay: Payment processing
  • ph-fss-member: FSS member management
  • ph-fss-activity: FSS marketing activities (group buy, flash sale, coupons)
  • ph-fss-report: Sales and analytics reporting
  • ph-fss-data: Data services
  • ph-fss-api: FSS API aggregation layer

lab-backend / ph-lab-common (Shared Libraries)

  • Sub-modules: common-core, common-security, common-datasource, common-log, common-redis, common-sftp, common-swagger

Data Flow

Consumer Request Flow (lab-wxapp → lab-backend)

  1. Mini-program calls uni.request → src/api/index.js → https://www.phlab.philips.com.cn/lab/{module}/*
  2. ph-lab-gateway receives request → AuthFilter extracts Bearer token → looks up Redis (LOGIN_TOKEN_KEY:{token}) → injects userId + userInfo headers → routes to downstream service
  3. XssFilter sanitizes JSON request bodies via EscapeUtil.clean()
  4. Downstream microservice processes request → returns { code: 200, data: ... }

Admin Request Flow (lab-admin-web → lab-manage-backend)

  1. Admin SPA calls Axios → https://www.phlab.philips.com.cn/ph-lab-admin/* or /lab-fss-admin/*
  2. lab-admin or lab-fss-admin receives request → Shiro session filter validates session from Redis
  3. CSRF token validated on mutating requests
  4. Service layer may call lab-backend microservices via Feign for data

Integration Points

External APIs

  • WeChat Mini-Program API: OAuth login, subscribe messages, template messages, QR code generation
  • Tencent VOD: Video upload and streaming
  • Aliyun SMS: SMS notifications
  • Sensors Analytics: Behavioral event tracking
  • Tuya IoT: Smart device integration
  • QQ Map LBS: Location services

Databases

  • MySQL: Primary relational data store (Druid connection pool)
  • Redis: Session storage, cache, distributed locks (Redisson)
  • Elasticsearch: Search and log storage

Message Queues

  • RabbitMQ: Async messaging across all backend services

Infrastructure

  • Deployment Model: Docker containers → Alibaba Cloud ACK (Kubernetes)
  • CI/CD: Jenkins (Dockerize → push to Aliyun ACR → deploy to K8s)
  • Service Discovery: Alibaba Nacos
  • Config Management: Nacos config center + environment-specific .env files
  • Static Assets: Aliyun OSS CDN
