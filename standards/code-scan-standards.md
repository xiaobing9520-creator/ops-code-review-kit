# 代码扫描标准参考文档

## 概述

本文档详细说明代码审核系统所依据的业界标准和规范，提供权威来源和具体应用指导。

## 1. MITRE CWE Top 25 (2025)

### 标准信息
- **全称**: Common Weakness Enumeration Top 25 Most Dangerous Software Weaknesses
- **发布机构**: MITRE Corporation
- **最新版本**: 2025年版
- **数据来源**: 基于39,080个CVE记录分析（2024年6月-2025年6月）

### Top 10 最危险弱点 (2025)

| 排名 | CWE ID | 弱点名称 | 危险评分 |
|------|--------|----------|----------|
| 1 | CWE-79 | 跨站脚本(XSS) | 45.54 |
| 2 | CWE-89 | SQL注入 | 28.72 |
| 3 | CWE-352 | 跨站请求伪造(CSRF) | 19.57 |
| 4 | CWE-20 | 输入验证不当 | 18.35 |
| 5 | CWE-78 | OS命令注入 | 16.44 |
| 6 | CWE-787 | 越界写入 | 15.98 |
| 7 | CWE-416 | 释放后使用(Use After Free) | 14.23 |
| 8 | CWE-22 | 路径遍历 | 13.67 |
| 9 | CWE-862 | 缺失授权检查 | 12.89 |
| 10 | CWE-476 | 空指针解引用 | 11.45 |

### 应用到审核系统
- **检测优先级**: Top 10弱点为最高优先级检测项
- **阻断标准**: 发现Top 5弱点时标记为阻断级问题
- **报告映射**: 所有发现的问题映射到对应的CWE编号

## 2. OWASP Top 10 (2021)

### 标准信息
- **全称**: Open Web Application Security Project Top 10
- **发布机构**: OWASP Foundation

### OWASP Top 10

| 排名 | 风险类别 | 说明 |
|------|----------|------|
| A01 | 失效的访问控制 | 用户可以访问超出其权限的功能或数据 |
| A02 | 加密失败 | 敏感数据未加密或使用弱加密 |
| A03 | 注入 | SQL、NoSQL、OS命令、LDAP注入等 |
| A04 | 不安全的设计 | 缺少或无效的安全控制设计 |
| A05 | 安全配置错误 | 默认配置、不完整配置、错误消息泄露 |
| A06 | 易受攻击和过时的组件 | 使用已知漏洞的库和框架 |
| A07 | 身份识别和身份验证失败 | 弱认证、会话管理问题 |
| A08 | 软件和数据完整性失败 | 不安全的反序列化、未验证的更新 |
| A09 | 安全日志和监控失败 | 缺少日志、监控不足 |
| A10 | 服务器端请求伪造(SSRF) | 未验证的URL请求 |

### 应用到审核系统
- **全面覆盖**: 审核系统检测所有10个类别
- **Web应用重点**: 对Web应用进行深度OWASP检查
- **合规报告**: 生成OWASP Top 10合规性报告

## 3. NIST SSDF (SP 800-218)

### 标准信息
- **全称**: Secure Software Development Framework
- **发布机构**: National Institute of Standards and Technology (NIST)
- **文档编号**: NIST Special Publication 800-218
- **发布日期**: 2022年2月（Version 1.1）

### 四大实践组

#### PO (Prepare the Organization) - 准备组织
- PO.1: 定义安全要求
- PO.2: 实施安全的开发环境
- PO.3: 了解和管理软件组件（供应链安全）
- PO.4: 使用安全的工具链
- PO.5: 维护安全文档

#### PS (Protect the Software) - 保护软件
- PS.1: 保护所有形式的代码
- PS.2: 提供机制验证软件完整性
- PS.3: 归档和保护每个软件版本

#### PW (Produce Well-Secured Software) - 生产安全软件
- PW.1: 设计软件以满足安全要求
- PW.2: 审查软件设计
- PW.4: 重用现有的、经过良好保护的软件
- PW.5: 创建源代码
- PW.6: 配置软件以具有安全设置
- PW.7: 审查代码以识别漏洞
- PW.8: 测试可执行代码以识别漏洞

#### RV (Respond to Vulnerabilities) - 响应漏洞
- RV.1: 识别和确认漏洞
- RV.2: 评估、优先级和修复漏洞
- RV.3: 分析漏洞以识别根本原因

### 应用到审核系统
- **PO.3映射**: 依赖包扫描对应PO.3实践
- **PW.7映射**: 代码审查对应PW.7实践
- **PW.8映射**: 测试覆盖率对应PW.8实践

## 4. ISO/IEC 27001:2022 Annex A 8.28

### 标准信息
- **全称**: Information Security Management - Secure Coding
- **标准编号**: ISO/IEC 27001:2022 Annex A Control 8.28

### 关键要求
1. 建立和维护安全编码标准
2. 实施代码审查流程（自动化工具 + 人工审查）
3. 集成安全测试到开发流程
4. 评估第三方组件的安全性

### 应用到审核系统
- 审核流程本身即满足8.28中"代码审查"要求
- 审核报告可作为ISO 27001审计证据

## 6. 12-Factor App

### 标准信息
- **创建者**: Heroku
- **用途**: 现代云原生应用开发方法论

### 十二要素（运维重点标记）

| # | 要素 | 运维重要性 |
|---|------|-----------|
| 1 | 代码库: 一个代码库，多个部署 | 中 |
| 2 | 依赖: 显式声明和隔离依赖 | 中 |
| 3 | **配置: 在环境中存储配置** | **高** |
| 4 | **后端服务: 当作附加资源** | **中** |
| 5 | 构建、发布、运行: 严格分离 | 中 |
| 6 | **进程: 以无状态进程运行** | **高** |
| 7 | 端口绑定: 通过端口绑定提供服务 | 低 |
| 8 | **并发: 通过进程模型进行扩展** | **中** |
| 9 | **易处理: 快速启动和优雅关闭** | **高** |
| 10 | 开发/生产环境等价 | 低 |
| 11 | **日志: 当作事件流** | **高** |
| 12 | 管理进程: 后台管理任务当作一次性进程 | 低 |

### 应用到审核系统
- 重点检查高运维重要性的要素（F3, F6, F9, F11）
- 纳入可靠性审核维度

## 7. CVSS 评分系统

### CVSS v3.1 评分范围
- **Critical**: 9.0-10.0
- **High**: 7.0-8.9
- **Medium**: 4.0-6.9
- **Low**: 0.1-3.9
- **None**: 0.0

### 应用到审核系统
- 统一使用CVSS等级定义分类发现项严重程度
- 安全审核中的发现项对标CVSS评分

## 标准应用矩阵

| 审核类别 | 主要标准 | 次要标准 | 阻断阈值 |
|---------|---------|---------|---------|
| 安全漏洞 | CWE Top 25, OWASP Top 10 | SANS Top 25 | CVSS >= 9.0 |
| 依赖安全 | NIST SSDF PO.3 | OWASP Dependency Check | CVSS >= 7.0 |
| 敏感信息 | ISO 27001 8.28, OWASP | - | 任何硬编码凭据 |
| 代码质量 | ISO 27001 8.28 | SonarQube规则 | 复杂度 >= 25 |
| 容器安全 | CIS Docker Benchmark | NIST SP 800-190 | 高危漏洞 |
| IaC安全 | CIS Cloud Benchmarks | - | 合规违规 |
| 运维就绪 | 12-Factor App, NIST SSDF | - | 缺少健康检查 |
| 测试覆盖 | NIST SSDF PW.8, ISO 27001 | - | 覆盖率 < 60% (警告) |
